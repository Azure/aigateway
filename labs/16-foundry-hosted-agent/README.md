Your team wants to run an agent in Microsoft Foundry, but the platform team needs every model call and every tool
call to be governed and visible in one place, with no keys to rotate or leak. In this lab you deploy a small
Microsoft Agent Framework agent to Foundry Hosted Agents. Its Foundry project has no model deployments, and the agent
holds no secrets: it reaches its model and its tools only through AI Gateway, which authorizes its Microsoft Entra
identities with an Azure role.

## How it works

The agent lives in [`infra/`](infra/), a complete azd project:

| File | What it does |
|---|---|
| [`infra/azure.yaml`](infra/azure.yaml) | Declares a Foundry project with no model deployments; `gateway-mcp`, a connection to the gateway's MCP server; `gateway-tools`, a Foundry toolbox that exposes that connection; and the hosted agent `gateway-agent`: Python 3.13, code deploy, 0.5 CPU, 1 GiB, Responses protocol |
| [`infra/src/gateway-agent/main.py`](infra/src/gateway-agent/main.py) | The agent: a model client that points at the gateway, and the toolbox |
| [`infra/src/gateway-agent/requirements.txt`](infra/src/gateway-agent/requirements.txt) | Pinned dependencies, compiled from `requirements.in`. Foundry builds the agent from this file. |

The agent has two outbound paths. Both end at AI Gateway, and neither uses a key:

- **Model.** An `OpenAIChatClient` points at the gateway's model endpoint, `/default/models/openai/v1/`, and sends
  your lab 02 alias as `model`. Instead of a key, it sends a Microsoft Entra token for the gateway's audience,
  `https://azure-api.net/aigateway/.default`, as `Authorization: Bearer`. In Foundry, the token belongs to the
  agent's own identity. Locally, it belongs to you.
- **Tools.** `FoundryToolbox` calls the `gateway-tools` toolbox in Foundry. The toolbox reaches the gateway's
  `/default/toolservers/learn/mcp` endpoint through the `gateway-mcp` connection, which signs in with the Foundry
  project's managed identity for the audience `https://azure-api.net/aigateway`. The agent never holds a credential
  for the MCP server.

Three identities call the gateway, and each one needs the **AI Gateway User** role, which lets it invoke models and
call MCP tools:

| Identity | Shown in **Access** › **Entra ID** as | Calls | Exists |
|---|---|---|---|
| The agent's identity, a Microsoft Entra Agent ID | `<account>-<project>-gateway-agent-AgentIdentity` (**Service principal**) | The model endpoint, from Foundry | After the first deploy |
| The Foundry project's managed identity | `<account>/projects/<project>` (**Service principal**) | The MCP endpoint, through the connection | After provisioning |
| You | Your account (**User**) | The model endpoint, when the agent runs locally | Already |

So you grant the role in two rounds: the project and yourself before you deploy, then the agent once Foundry has
created its identity.

| Piece | Name in this lab | Owner |
|---|---|---|
| Model alias | Your alias from lab 02, in `AI_GATEWAY_MODEL` | AI Gateway |
| MCP server | `learn`, at `/default/toolservers/learn/mcp` | AI Gateway |
| Role | **AI Gateway User**, `caad7a21-134e-43f4-a550-c5ffc17e051c`, on the gateway | AI Gateway |
| Foundry resource and project | In resource group `rg-<env>`; the project is named after the azd environment | Foundry, created by azd |
| Connection and toolbox | `gateway-mcp` and `gateway-tools` | Foundry, created by azd |
| Hosted agent | `gateway-agent` | Foundry, created by azd |

Foundry runs the agent. AI Gateway decides what each identity may call, counts its tokens, and records every call.

## Read the agent

[`main.py`](infra/src/gateway-agent/main.py) is the whole agent. The model client and the toolbox are the only
places it talks to the network, and neither holds a key:

```python
credential = DefaultAzureCredential(
    exclude_managed_identity_credential=not os.environ.get("FOUNDRY_HOSTING_ENVIRONMENT"),
)

get_gateway_token = get_bearer_token_provider(credential, AI_GATEWAY_SCOPE)

async def gateway_token() -> str:
    return get_gateway_token()

client = OpenAIChatClient(
    model=model,
    base_url=f"{gateway_url}/default/models/openai/v1/",
    api_key=gateway_token,
)

tools = FoundryToolbox(credential, timeout=60)
```

- `DefaultAzureCredential` signs in as the agent's identity in Foundry, which sets `FOUNDRY_HOSTING_ENVIRONMENT` in
  the agent's container. Locally, it skips the managed identity probe and uses your Azure CLI or azd sign-in.
- The OpenAI SDK calls `gateway_token` before each request and sends the result as `Authorization: Bearer`, so the
  token refreshes on its own.
- `FoundryToolbox` reads the toolbox's endpoint from `TOOLBOX_ENDPOINT`, and signs in to Foundry with the same
  credential. The toolbox, not the agent, signs in to the gateway's MCP endpoint.
- `HandshakeClient` opens the toolbox connection with the MCP `initialize` handshake. Otherwise the MCP SDK picks
  the stateless version `2026-07-28`, which the toolbox offers, and the toolbox speaks it to the gateway's `learn`
  server. That server keeps the versions of its Microsoft Learn backend, so it answers with `403`.
- The instructions ask the model to answer from the search results, and to fetch a whole article only when they
  don't answer the question. An article is long: with the 10,000 tokens per minute that the quick start and
  [lab 02](../02-first-model-call/README.md) give the model deployment, the model call that reads it can fail with
  `429`.

`ResponsesHostServer` serves the agent on the Responses protocol at port 8088, the same way locally and in Foundry,
and creates the agent for each request. The agent sets `store` to `false` on its model calls, because the hosting
server already keeps the conversation history.

```py
"""A Foundry hosted agent whose model calls and MCP tool calls both go through AI Gateway, without keys.

The agent has no Foundry model deployment and no direct route to a tool:
- Model: it calls the gateway's OpenAI-compatible model endpoint with an alias and a Microsoft Entra token for the
  gateway's audience.
- Tools: it calls a Foundry toolbox, which reaches the gateway's MCP server through a RemoteTool connection that signs
  in with the Foundry project's managed identity.

In Foundry, the tokens come from the agent's managed identity. Locally, `azd ai agent run` uses your Azure CLI sign-in.
To run it without azd, copy .env.example to .env, install requirements.txt in a virtual environment, and run
`python main.py`.
"""

import os

import mcp
from agent_framework import Agent
from agent_framework.openai import OpenAIChatClient
from agent_framework_foundry_hosting import FoundryToolbox, ResponsesHostServer
from azure.identity import DefaultAzureCredential, get_bearer_token_provider
from dotenv import load_dotenv

load_dotenv()


class HandshakeClient(mcp.Client):
    """An MCP client that opens its connection with the initialize handshake.

    By default, the MCP SDK negotiates the stateless MCP version 2026-07-28 when the server offers it, and Foundry
    toolboxes do. The toolbox then speaks 2026-07-28 to the gateway's MCP server, and a server that supports only
    earlier versions, like one whose backend is the Microsoft Learn MCP server, answers with HTTP 403. The handshake
    keeps the whole chain on a version that the gateway's MCP server supports.
    """

    def __init__(self, *args, mode: str = "legacy", **kwargs) -> None:
        super().__init__(*args, mode=mode, **kwargs)


# Agent Framework creates its MCP clients from mcp.Client, so this applies to the toolbox connection.
mcp.Client = HandshakeClient

# The audience of AI Gateway's runtime endpoints
AI_GATEWAY_SCOPE = "https://azure-api.net/aigateway/.default"

INSTRUCTIONS = """
You answer questions about Microsoft and Azure technologies.
- Search the Microsoft Learn tools before you answer, and cite the URLs you used.
- Answer from the search results. Fetch a whole article only when they don't answer the question: articles are long,
  and their tokens count toward the model's limits.
- If the tools don't cover the question, say so instead of guessing.
- Keep answers under 150 words.
"""


def required(name: str) -> str:
    value = os.environ.get(name, "").strip()
    if not value:
        raise RuntimeError(f"Set {name}. With azd, run: azd env set {name} <value>")
    return value


# Foundry sets FOUNDRY_HOSTING_ENVIRONMENT in the agent's container. Locally, skip the managed identity probe, so that
# the credential goes straight to your Azure CLI or azd sign-in.
credential = DefaultAzureCredential(
    exclude_managed_identity_credential=not os.environ.get("FOUNDRY_HOSTING_ENVIRONMENT"),
)


def create_agent() -> Agent:
    gateway_url = required("AI_GATEWAY_URL").rstrip("/")
    model = required("AI_GATEWAY_MODEL")
    get_gateway_token = get_bearer_token_provider(credential, AI_GATEWAY_SCOPE)

    async def gateway_token() -> str:
        return get_gateway_token()

    # The SDK sends the token as Authorization: Bearer, and asks for a fresh one before each call.
    client = OpenAIChatClient(
        model=model,
        base_url=f"{gateway_url}/default/models/openai/v1/",
        api_key=gateway_token,
    )

    # FoundryToolbox reads the toolbox endpoint from TOOLBOX_ENDPOINT, and signs in to Foundry with the same credential.
    tools = FoundryToolbox(credential, timeout=60)

    return Agent(
        client=client,
        name="gateway-docs-agent",
        instructions=INSTRUCTIONS,
        tools=tools,
        # Foundry keeps the conversation history, so the model call doesn't need to store it.
        default_options={"store": False},
    )


if __name__ == "__main__":
    # The server creates the agent for each request, and closes its toolbox connection afterward.
    ResponsesHostServer(agent=create_agent).run()
```

### Add the token limit

Find the alias by the name that apps send, which works even when a portal-created alias contains `/`.
`az aigateway model-alias update --policies` replaces the alias's whole policy array, so these commands keep its
other policies:

<details open><summary>Bash</summary> <!-- gh -->

```bash title="Bash"
# Find the alias's resource name from the name that apps send
ALIAS_NAME="$(az aigateway model-alias list -g "$RG" --gateway-name "$GATEWAY" \
  --query "[?properties.aliasName=='$AI_GATEWAY_MODEL'].name | [0]" -o tsv)"
echo "🔖 Alias resource name: $ALIAS_NAME"

# Write the alias's other policies, plus a limit of 1,000 tokens per minute counted per caller identity, to a file
az aigateway model-alias show -g "$RG" --gateway-name "$GATEWAY" -n "$ALIAS_NAME" -o json \
  | jq -c '[(.properties.policies // [])[] | select(.type != "tokenLimit") | del(.scope)] + [{type:"tokenLimit",period:"minute",count:1000,counterKey:["identity"]}]' > policies.json

# Replace the alias's whole policy array with the file's, and print the new array
```

## Go further

- **Narrow the roles.** AI Gateway User covers models and tools. The agent's identity only calls the model, and the
  project's managed identity only calls the MCP server, so assign them **AI Gateway Models User** and **AI Gateway
  Tools User** instead: in the wizard, pick **All models** or **All tools** as the scope. Running locally, you need
  both. [Go keyless with Microsoft Entra ID and RBAC](../11-entra-rbac/README.md) scopes roles further, to one alias
  or MCP server.
- **Use an API key where Entra isn't an option.** Create a key in **Access** › **API keys**, and send it as the
  SDK's API key to the model endpoint, which accepts a key as `Authorization: Bearer` or in an `api-key` header. The
  MCP endpoint accepts keys only in the `api-key` header. Send a key in one header only: the gateway rejects a
  request that has both `api-key` and `Authorization` with `400` and "Specify either an API key or an Authorization
  header, not both".
- **Lock down egress.** Foundry can restrict where a hosted agent may connect. Allow only your gateway's host name,
  so the gateway is the agent's only way out. See the
  [egress control sample](https://github.com/microsoft-foundry/foundry-samples/tree/main/samples/python/hosted-agents/agent-framework/responses/18-egress-control).
- **Use another framework.** Swap the agent's internals for the OpenAI Agents SDK or LangGraph, as in
  [Connect agent frameworks to models and tools](../15-agent-frameworks/README.md). The gateway settings stay the
  same.
- **Charge the agent back.** Attribute its tokens and estimated cost with
  [Attribute tokens and cost with OpenTelemetry](../14-otel-chargeback/README.md).
