Your agent teams want tools: documentation search, ticketing, internal APIs. If every agent connects to every
tool server directly, you end up with credentials in many places and no single point of control. In this lab
the platform team publishes **one governed MCP endpoint** on the gateway, starting with the public Microsoft
Learn MCP server, so agents get tools through the same front door they already use for models.

## How it works

An **MCP server** in AI Gateway is a federation point. You give it one or more **backends**, and the gateway
publishes all their tools at one Streamable HTTP endpoint:
`<gateway-url>/default/toolservers/<server-name>/mcp`.

| Backend type | What you provide | What clients see |
|---|---|---|
| **MCP server** (remote) | The **Endpoint URL** of a server that speaks Streamable HTTP | The server's tools |
| **OpenAPI specification** | A JSON or YAML OpenAPI document (upload, URL, or inline) | Selected operations as tools. The operation summary or description becomes the tool description. |
| **From Azure** | An existing API or MCP server in Azure: an API Management API, an Azure Functions MCP tool trigger, a Logic Apps or API Center MCP server, a Container Apps session pool, or an MCP server hosted in a Connector Namespace that wraps SaaS connectors like Microsoft 365, SharePoint, GitHub, or Salesforce | The source's tools |

Connector tools come from an Azure Connector Namespace. Create the MCP server there and authorize its connections in
Azure, then choose **Import from Azure** on **MCP servers**, or **Add backend** › **From Azure** in an MCP server,
and select it, as in the product's
[Discover and import Azure-hosted MCP servers](https://ai.gateway.azure.com/docs/toolservers/import-from-azure)
walkthrough. The gateway references the source without owning it, so removing the backend or the gateway leaves
the namespace and its connections in place.

Each backend can have a **namespace**. The gateway prefixes that backend's tools with it, as in
`learn_microsoft_docs_search`, so two backends can expose tools with the same name without conflict.

The gateway authenticates **clients**. In this lab they send a runtime key as `Authorization: Bearer <key>`.
It authenticates to each **backend** separately, with **None**, **API Key** (one or more header names and
values), **OAuth 2.0** (a **Single shared application**, or **On behalf of** each caller with their Microsoft
Entra permissions), or **Managed identity**. Backend credentials are stored securely, are never exposed to
clients, and appear under **Connections**.

> [!NOTE]
> Registering a backend doesn't mean that AI Gateway translates every backend protocol into MCP. Pick the
> backend type that matches what the backend actually serves.

## Register the Learn MCP server

Pick one track. Each track creates the same MCP server: **`learn`**, with one backend, the public Microsoft
Learn MCP server at `https://learn.microsoft.com/api/mcp`, under the namespace `learn`. That server needs no
credentials, so the backend authentication is **None**.

### Start the workflow

Open the [AI Gateway portal](https://ai.gateway.azure.com) and select your gateway from the gateway switcher.
Select **MCP servers** › **Add MCP server**. The full-page **Create MCP server** workflow has three steps:
**Basic info**, **Backends**, and **Tools**.

### Describe the server

On **Basic info**, set:

| Field | Value |
|---|---|
| **Name** | `learn` (part of the endpoint URL; it can't be changed after creation) |
| **Display name** | `Microsoft Learn` |
| **Description** | `Search and fetch official Microsoft documentation and code samples.` |
| **Supported MCP versions** | `2025-06-18` (required: select at least one version that every backend supports) |

Agents and people read the description to decide when to use the server, so keep it specific. The display name
must be unique among the MCP servers of the gateway. You learn more about the versions in
[Choose supported MCP versions](#choose-supported-mcp-versions). Select **Next**.

### Add the Learn backend

On **Backends**, select **Add backend** › **MCP server**. In **Add MCP backend**, set:

| Field | Value |
|---|---|
| **Endpoint URL** | `https://learn.microsoft.com/api/mcp` |
| **Authentication** | **None** |
| **Namespace** | `learn` |

Select **Add**. The backend appears in the table with its **URL**, **Type**, **Authentication**, **Namespace**,
and **Required** columns. Leave **Required** on.

### Publish all tools

Select **Next**. The portal saves the server with **Allow all tools**, which publishes every current and future
tool from its backends. You narrow this down in
[Control which tools agents can call](../05-mcp-tool-controls/README.md). If the **Tools** step opens, keep
**Allow all tools** and select **Create**.

### Copy the endpoint

Open `Microsoft Learn` from **MCP servers**. Under **Basics**, check the **Description**: if it reads
"Federated MCP server providing tools from: learn", select **Edit**, enter the description again, and select
**Save**. Under **Endpoints**, copy the **Endpoint URL**. It ends in `/default/toolservers/learn/mcp`.

> **Checkpoint**
> **MCP servers** lists `Microsoft Learn` with the namespace `learn`, and its details page shows an
> **Endpoint URL**, **Supported MCP versions** `2025-06-18`, and one backend with the namespace `learn`.

### Create the registration

`az aigateway mcp create` registers the MCP server. `--endpoints` takes the backends as a JSON array.

<details open><summary>Bash</summary> <!-- gh -->

```bash title="Bash"
# Register the learn MCP server, with the public Learn MCP server as its one backend, under the namespace learn
az aigateway mcp create -g "$RG" --gateway-name "$GATEWAY" -n learn \
  --display-name "Microsoft Learn" \
  --description "Search and fetch official Microsoft documentation and code samples." \
  --endpoints '[{"kind": "mcp", "namespace": "learn", "required": true,
                 "mcp": {"url": "https://learn.microsoft.com/api/mcp", "transport": "streamableHttp"}}]' \
  --query "{name:name,mcpEndpoint:properties.gatewayEndpoints[0].url}" &&
  echo "🔌 MCP server learn is ready"
```
</details> <!-- gh -->

<details><summary>PowerShell</summary> <!-- gh -->

```powershell title="PowerShell"
# Write the backends to a file, so that PowerShell passes the JSON to az unchanged
ConvertTo-Json -Depth 10 -Compress -InputObject @(
  @{ kind = 'mcp'; namespace = 'learn'; required = $true
     mcp  = @{ transport = 'streamableHttp'; url = 'https://learn.microsoft.com/api/mcp' } }
) | Set-Content -Path endpoints.json

# Register the learn MCP server, with the public Learn MCP server as its one backend, under the namespace learn
az aigateway mcp create -g $RG --gateway-name $GATEWAY -n learn `
  --display-name "Microsoft Learn" `
  --description "Search and fetch official Microsoft documentation and code samples." `
  --endpoints "@endpoints.json" `
  --query "{name:name,mcpEndpoint:properties.gatewayEndpoints[0].url}"
if ($?) { Write-Host "🔌 MCP server learn is ready" }
Remove-Item endpoints.json
```
</details> <!-- gh -->

`-n learn` is the MCP server name. `mcp create` fails with `This MCP registration already exists; use mcp update.`
if the name is taken, so change an existing registration with `az aigateway mcp update` or the `mcp source`
commands, as in the next section.

```bicep
// Registers the public Microsoft Learn MCP server as a federated MCP server in an existing AI Gateway. main.bicep calls
// it after lab 01's gateway template, and you can also deploy it on its own to a gateway you already have.
// Clients call one governed endpoint, <gateway-url>/default/toolservers/<serverName>/mcp,
// and the gateway publishes each backend's tools with a namespace prefix (<namespace>_<tool>).
// Set secondNamespace to add the same public server as a second, optional backend and see namespacing at work.
// A required backend has mode failClosed: tool discovery fails if it fails. An optional one has mode failOpen: the
// gateway skips it. displayName must be unique among the MCP servers of the gateway.
// Set supportedVersions to pin the MCP protocol versions that clients can negotiate.
// Set apiKeyName to also create a runtime API key for your clients. Its value is never an output.

@description('Name of the existing AI Gateway (Microsoft.ApiManagement/aigateways).')
param gatewayName string

@description('MCP server name. It becomes part of the endpoint URL and cannot be changed after creation.')
param serverName string = 'learn'

@description('Display name shown in the portal catalog and details page.')
param displayName string = 'Microsoft Learn'

@description('Description that helps people and agents understand what the tools do.')
param serverDescription string = 'Search and fetch official Microsoft documentation and code samples.'

@description('Namespace for the first backend. Its tools are published as <namespace>_<tool>.')
param namespace string = 'learn'

@description('URL of the first backend MCP server (Streamable HTTP).')
param mcpUrl string = 'https://learn.microsoft.com/api/mcp'

@description('Optional namespace for a second backend. Leave empty to register one backend only.')
param secondNamespace string = ''

@description('URL of the optional second backend MCP server (Streamable HTTP).')
param secondMcpUrl string = 'https://learn.microsoft.com/api/mcp'

@description('Comma-separated MCP protocol versions the server supports, for example 2025-06-18 or 2026-07-28,2025-06-18. Every MCP backend must support every version you list. Leave empty to keep the server\'s current list, or the legacy defaults on a new server: 2025-06-18, 2025-03-26, and 2024-11-05.')
param supportedVersions string = ''

@description('Optional runtime API key to create for the MCP clients, for example app-first-call. Leave empty to create none.')
param apiKeyName string = ''

var versions = empty(supportedVersions) ? {} : { versions: split(replace(supportedVersions, ' ', ''), ',') }

var primaryEndpoint = {
  namespace: namespace
  kind: 'mcp'
  mode: 'failClosed'
  mcp: {
    endpoint: {
      url: mcpUrl
    }
    transport: 'streamableHttp'
  }
}

var secondEndpoint = {
  namespace: secondNamespace
  kind: 'mcp'
  mode: 'failOpen'
  mcp: {
    endpoint: {
      url: secondMcpUrl
    }
    transport: 'streamableHttp'
  }
}

#disable-next-line BCP081
resource gateway 'Microsoft.ApiManagement/aigateways@2026-11-01' existing = {
  name: gatewayName
}

#disable-next-line BCP081
resource workspace 'Microsoft.ApiManagement/aigateways/workspaces@2026-11-01' existing = {
  parent: gateway
  name: 'default'
}

#disable-next-line BCP081
resource toolServer 'Microsoft.ApiManagement/aigateways/workspaces/toolServers@2026-11-01' = {
  parent: workspace
  name: serverName
  properties: union({
    displayName: displayName
    description: serverDescription
    toolServerType: 'mcp'
    endpoints: empty(secondNamespace) ? [ primaryEndpoint ] : [ primaryEndpoint, secondEndpoint ]
  }, versions)
}

#disable-next-line BCP081
resource apiKey 'Microsoft.ApiManagement/aigateways/apiKeys@2026-11-01' = if (!empty(apiKeyName)) {
  parent: gateway
  name: apiKeyName
  properties: {
    displayName: apiKeyName
  }
}

output toolServerId string = toolServer.id
output supportedVersions array = toolServer.properties.?versions ?? []
output mcpEndpoint string = 'https://${gateway.properties.frontend.defaultHostname}/default/toolservers/${serverName}/mcp'
```

## Choose supported MCP versions

MCP is versioned by date. A client opens a connection by naming the protocol version it speaks, and the server
answers with the version both sides will use. AI Gateway negotiates one version for the whole MCP server, so
that version must work with **every backend** behind it.

| Supported MCP versions | What clients get |
|---|---|
| Not configured | The legacy defaults: `2025-06-18`, `2025-03-26`, and `2024-11-05`. The details page lists them, and **Edit** shows **Not configured**. Servers that you create with the CLI, Bicep, or Terraform without a list get them. |
| A list that you choose | Version restrictions. Clients negotiate only a version in the list, and a request whose `MCP-Protocol-Version` header names any other version is rejected with `400`. |

You can choose `2026-07-28`, `2025-11-25`, `2025-06-18`, `2025-03-26`, and `2024-11-05`. Version
`2026-07-28` is the stateless revision of the specification: it replaces the `initialize` handshake and
sessions with a `server/discover` request, and every request carries `MCP-Protocol-Version`, `Mcp-Method`, and
`Mcp-Name` headers plus metadata in `params._meta`. Select it only when every backend supports it, and use an
MCP SDK that implements it rather than hand-written requests.

In this lab, pin the server to `2025-06-18`. At the time of writing, that's the version the Microsoft Learn MCP
server negotiates, so both backends, `learn` and `docs`, support it.

```py
"""List, and optionally call, the tools that an AI Gateway MCP server publishes.

Usage:
    export AI_GATEWAY_URL="<gateway-url>"
    export AI_GATEWAY_API_KEY="..."      # never commit this value
    python list_tools.py [server-name] [tool-name] [query]

Examples:
    python list_tools.py learn
    python list_tools.py learn learn_microsoft_docs_search "What is AI Gateway?"

Set AI_GATEWAY_MCP_ENDPOINT to use a full MCP endpoint URL instead of building it from AI_GATEWAY_URL.
"""

import asyncio
import os
import sys

import httpx
from mcp import ClientSession
from mcp.client.streamable_http import streamable_http_client
from mcp.shared.exceptions import McpError


def endpoint(server: str) -> str:
    if os.environ.get("AI_GATEWAY_MCP_ENDPOINT"):
        return os.environ["AI_GATEWAY_MCP_ENDPOINT"]
    base = os.environ.get("AI_GATEWAY_URL")
    if not base:
        sys.exit("Set AI_GATEWAY_URL to the gateway runtime URL, for example https://aigw-labs-k3v7qz2m9xw4p.eastus2-01.ai.gateway.azure.com")
    return f"{base.rstrip('/')}/default/toolservers/{server}/mcp"


async def main() -> None:
    server = sys.argv[1] if len(sys.argv) > 1 else "learn"
    tool = sys.argv[2] if len(sys.argv) > 2 else None
    query = sys.argv[3] if len(sys.argv) > 3 else "What is Azure AI Gateway?"
    api_key = os.environ.get("AI_GATEWAY_API_KEY")
    if not api_key:
        sys.exit("Set AI_GATEWAY_API_KEY to a runtime key from Access > API keys")

    url = endpoint(server)
    print(f"MCP endpoint: {url}")

    # The gateway authenticates the client with the runtime key, sent as a bearer token.
    async with httpx.AsyncClient(headers={"Authorization": f"Bearer {api_key}"}, timeout=60) as http_client:
        async with streamable_http_client(url, http_client=http_client) as (read, write, _):
            async with ClientSession(read, write) as session:
                init = await session.initialize()
                print(f"Server: {init.serverInfo.name}  protocol: {init.protocolVersion}\n")

                result = await session.list_tools()
                for t in result.tools:
                    description = " ".join((t.description or "").split())[:70]
                    print(f"{t.name:<45} {description}")
                print(f"\n{len(result.tools)} tools published")

                if tool:
                    print(f"\nCalling {tool} with query: {query}")
                    try:
                        call = await session.call_tool(tool, {"query": query})
                    except McpError as error:
                        print(f"The tool call failed: {error}")
                        return
                    text = "\n".join(c.text for c in call.content if c.type == "text")
                    if call.isError:
                        print(f"The tool call failed: {text}")
                        return
                    print(text[:600] + "\n...")


if __name__ == "__main__":
    asyncio.run(main())
```

### Send a raw JSON-RPC request

The docs show the smallest possible request: a single JSON-RPC `tools/list` call. Streamable HTTP clients
should also accept both JSON and SSE responses.

```bash
# Send a single tools/list request, with your runtime key as a bearer token
echo "🔧 tools/list response from learn:"
curl -sS "${AI_GATEWAY_URL%/}/default/toolservers/learn/mcp" \
  -H "Authorization: Bearer $AI_GATEWAY_API_KEY" -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
```

The answer is JSON or an SSE `data:` line with a `result.tools` array. If the server answers with a JSON-RPC
`error` instead, it requires the full handshake. Use the script, which runs it for you.

### Prove that the gateway checks the caller

Send the same request without the key:

```bash
# Send the same request without the Authorization header
echo "🚦 Expect 401 Unauthorized without a key:"
curl -sS -o /dev/null -w "🚦 HTTP %{http_code}\n" "${AI_GATEWAY_URL%/}/default/toolservers/learn/mcp" \
  -H "Content-Type: application/json" -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
```

The gateway rejects the request, typically with `🚦 HTTP 401`, and no backend is called. Microsoft Learn is public,
but your MCP endpoint isn't.

## Go further

- **Control the catalog.** Publish only approved tools, block risky ones, and rate-limit the server in
  [Control which tools agents can call](../05-mcp-tool-controls/README.md).
- **Screen tool traffic.** Content safety also screens tool inputs and responses on MCP servers. See
  [Screen prompts and responses with content safety](../08-content-safety/README.md).
- **Go keyless.** Grant callers the **AI Gateway User** role and send a Microsoft Entra token instead of a
  runtime key. See [Go keyless with Microsoft Entra ID and RBAC](../11-entra-rbac/README.md).
- **Watch tool traffic.** When Application Insights is configured, tool executions appear in **Monitoring** ›
  **Tools**. See [Monitor usage, cost, and traces](../13-monitoring/README.md).
- **Onboard GitHub.** Add the GitHub MCP server, `https://api.githubcopilot.com/mcp/`, as an **MCP server**
  backend with **API Key** authentication: **Header name** `Authorization` and **Value**
  `Bearer <your-github-token>`. The gateway stores the token, and clients never see it.
- **Use OAuth backends.** Sign in once for a shared backend account with
  [Connect shared OAuth backends](https://ai.gateway.azure.com/docs/toolservers/connect-shared-oauth-backends), or
  call the backend with each caller's own Microsoft Entra permissions with
  [Access MCP server backends with user credentials](https://ai.gateway.azure.com/docs/toolservers/access-backends-with-user-credentials).
- **Import from Azure.** Add API Management APIs, Azure Functions MCP tools, and Connector Namespace servers with
  [Discover and import Azure-hosted MCP servers](https://ai.gateway.azure.com/docs/toolservers/import-from-azure).
- **Give tools to an agent.** Point an agent framework at the endpoint in [Connect agent frameworks to models and tools](../15-agent-frameworks/README.md).
